## 1. Bugs

### High

- [x] **H-01** **[`systems/views_noauth.py`](systems/views_noauth.py#L323) ~323 (IPXEAPIView), (verified).**
  - What happens: if the client IP matches NICs but none of them is `bootable`, the code reaches `if nic==None:` and then reads `nic.bootable`. That raises `AttributeError` and returns HTTP 500.
  - Also: `template` and `context` are not defined at that point (ruff F821).
  - When it fires: this is exactly the state after the stateful installer POSTs `/systems/?self {"netboot":...}` and reboots. So the "System not set to bootable… Attempting local boot" path in the `ipxe` template never renders.
  - **Done:** fixed in `ba0f289` on branch `fix-ipxe-nonbootable-nic` (off `main` at `146e36b`; pushed 2026-10-15 as PR #183, merged as `8d6cdfd`). The same commit also fixes the undefined `template` when an image has no OS distro, and removes the unreachable `hasattr(nic, "bootable")` check. Tests are in [`systems/tests.py`](systems/tests.py), and they will conflict with H-02's and H-03's tests in that file at merge time.
- [x] **H-02** **[`systems/views.py`](systems/views.py#L906-L913) ~906-913 (SystemPowerAPIView, `reset`), (verified).** `ipmi.chassis_control_power_cycle()` sits outside the `except`. A successful hard reset is therefore followed by a power cycle as well. The admin version at [`systems/admin.py:316-319`](systems/admin.py#L316-L319) is correct.
  - **Done:** fixed in `7e6be8a` on branch `fix-api-reset-double-cycle` (off `main` at `146e36b`; pushed 2026-10-15 as PR #184, merged as `88ada23`). The bare `except:` is narrowed to `except Exception:`. Tests are in [`systems/tests.py`](systems/tests.py), and they will conflict with H-01's and H-03's tests in that file at merge time.
- [x] **H-03** **[`systems/models.py:103`](systems/models.py#L103), (verified).**
  - `config = {}` is a class-level mutable dict, so every `System` instance shares it.
  - `flatten_config` mutates it, so config leaks between instances.
  - Related: `+=` at ~165/168/199/202 raises `KeyError` if no distro seeded the key.
  - **Done:** fixed in `42ee125` on branch `fix-system-config-leak` (off `main` at `146e36b`; pushed 2026-10-15 as PR #185, merged as `d306b1e`). Tests are in [`systems/tests.py`](systems/tests.py). Follow-up: D-48.

- [x] **H-06** **[`install_scripts/init_mpcc.sh:86-92`](install_scripts/init_mpcc.sh#L86-L92).**
  - When it fires: on a bare-metal install, `install_mpcc.sh:321` runs it without `-d`.
  - Cause: `MPROV_MPCC_HOSTNAME`, `MPROV_DOMAINNAME`, `MPROV_MPCC_IPs` and `ALLOWED_HOSTS` are all unset in that case. They only come from `stack.env`, loaded through `env_file:` in the compose files.

Only set values are joined. `hostname.domain` is added only when both are set. If none are set, an existing `ALLOWED_HOSTS` line is left alone. The block was tested on its own with sample envs; the container wasn't run.
