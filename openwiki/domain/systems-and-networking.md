# Systems & Networking

These two apps hold the physical inventory: machines ([systems/](../../systems/)) and the L2/L3 topology they plug into ([networks/](../../networks/)). Their save/delete signals are the primary producers of jobs into the [Job Queue](jobs-and-scripts.md), which jobservers execute as pxe/dns/dhcp/image updates. All endpoints inherit [MProvView](../architecture/api-foundation.md) conventions, including `?detail` nested reads.

## Systems (`systems/`)

Key models (`systems/models.py`):

- **System** — a provisioned machine: `hostname`, `stateful` flag, `provision` flag (see [Provisioning and PXE Boot](#provisioning-and-pxe-boot)), FK to `SystemImage`, M2M to `DiskLayout` (see [OS & Disk Management](os-and-disk-management.md)), M2Ms to scripts/Ansible content, and a read-only `config` dict (cached property) merged by `common.render_config()`/`flat_config()` in `common/__init__.py` — the single implementation of config inheritance (the old `System.flatten_config()` is gone). Layers apply **OS Distro → System Groups (by name) → System Image → System**; a system's groups are its own plus its image's, each applied once. `install_kernel_cmdline` and `initial_mods` append down the stack (a leading `=` replaces everything above); `tmpfs_root_size`/`prov_interface` overwrite (0/empty inherits); `config_params` YAML merges by top-level key (invalid YAML or a non-mapping is skipped and reported); scripts and Ansible playbooks/roles/collections are the union of every layer's slugs (`systems/test_render_config.py`). The jobserver's script runner merges the same way — keep the two in step.
- **NetworkInterface** — belongs to a System, attaches one-to-one to a `SwitchPort`, carries `ipaddress`/MAC/bootable flags; IPv6 link-local/guarded-global addresses are computed alongside. Its `hostname` is a copy of the System's, kept in step by `NetworkInterface.save()`, by `System.save()` (which updates the NIC copies in the same transaction on rename, so DHCP/DNS and register_IPv6_ll.py never see a stale name), and by read-only `hostname` in both NIC serializers (#382, `systems/test_nic_hostname.py`).
- **SystemBMC** — "Power Management" credentials per system (inline max 1; password field uses `PasswordInput` and is never exposed on flat API lists). On the API the password is served only when the request **comes from that system itself** — one of its NIC addresses is the socket peer (per `TRUSTED_PROXIES`, #319) — via `/systembmcs/<pk>/`, `?system=ID&detail` (the query mprov_scripts' `setupBMC.py` makes), or `?self` (resolves the caller's NIC to its system; `?self&system=<other>` → 404). Any other detail read is served through `SystemBMCDetailNoPasswordSerializer` with the password left out, so one unscoped GET cannot dump every BMC password (issue #316, `systems/views.py`, `systems/test_bmc_password_own_system.py`). An empty-string `password` on POST/PATCH is deleted before validation.
- **SystemImage** — the PXE-bootable image definition (slug PK, `version`, `needs_rebuild`, `customIPXE`). It is a config-inheritance layer in its own right (distro → image's groups → image) and has the same cached `config` property as System; the `/systemimages/` serializers serve it read-only in list and detail so the jobserver's script runner can read the merge instead of redoing it (`systems/models.py`, `systems/test_render_config.py`).
- **SystemSerialHistory** (#60, migration 0074) — append-only history of `System.serial` changes: old/new serial, timestamp, source (`admin`/`api`/`nads`/`node`), acting user. Sources writing it: the admin form, the API serializer, N.A.D.S. registration (optional serial field), and the node itself via `POST /systems/?self {"serial": ...}`. dmidecode placeholders ("To Be Filled By O.E.M." etc.) are ignored by `clean_serial()`; node reports use queryset `update()` so no jobs are queued, and changes log to the `mprov.serial` logger. Shown as a collapsed read-only inline; the API serializer and search expose serial (`systems/test_serial.py`).
- Plus `SystemGroup`, `SystemModel`, `SystemLocation`, and `NADSSystem` (switch-based auto-discovery: an NADS post_save copies the discovered MAC onto the system's bootable NIC).

**Signals are the behavior**: saving a System/NIC/BMC queues `pxe-update`, `dns-update`, `dhcp-update` jobs; saving a `SystemImage` bumps its version, clears assigned jobservers, and queues `image-update`; deleting an image queues per-server `image-delete`. These write into the [job queue](jobs-and-scripts.md) — mPCC never touches TFTP/DNS directly.

**Admin** (`systems/admin.py`): `SystemAdmin` embeds a `NetworkInterfaceInline` (custom `NetForm` widgets; a formset restricts `switch_port` choices to unassigned ports — the IP Address widget deliberately has no narrowing style, enforced by `systems/test_nic_inline.py`) and a `BMCInline`. IPMI power actions (`sys_on/off/cycle/pxe/pxe_efi`) use `pyipmi` plus raw `ipmitool` with the `IPMI_PASSWORD` env var. A `bulk_update` admin action (template `systems/templates/admin/system_bulk_change_form.html`) can set `provision`, and a `_copy_to_new` button clones systems (the copy blanks `serial`, #60). A bulk **"Set BMC credentials"** admin action on the System and System Group lists (`systems/bmc_credentials.py`, #374) sets the stored BMC user/password on many systems at once (blank = keep) via queryset `update()` — it queues **no jobs** (500 BMCs = 0 jobs), logs one line to `mprov.bmc` without the password, and stamps new `SystemBMC.credentials_changed` (migration 0075, shown as the BMC-link tooltip); `store` mode changes mPCC-stored credentials only — the same form now also offers **change** and **check** modes that push to the BMCs via the [bmcrotate app](#bmc-credential-changes-bmcrotate). An **"Add range"** button on the System changelist (`systems/range_wizard.py`, `AdminWizardModel`, #38) creates up to 1000 systems from a hostname pattern like `c[001-100]` — optionally copying settings (never NICs/BMC/serial) from an existing system — plus per-system NICs (counting IPs, pasted MACs; a blank MAC lets N.A.D.S. fill it), switch ports from a pattern like `1/[1-40]`, and BMCs (counting IP/user/password). Preview validates everything and Create is all-or-nothing in one transaction; the BMC password is held in the session, never echoed to the browser. On the SystemImage change page a **"Rebuild now"** button (#176, `templates/admin/systems/systemimage/submit_line.html`) sets `needs_rebuild` so the existing signal queues one image-update job and bumps the version; the changelist action is "Rebuild selected images now" (`systems/test_image_rebuild_now.py`). The System-only "Copy to new" `submit_line.html` lives at `templates/admin/systems/system/` so it no longer appears on other app pages (#479). Both `SystemAdmin` and `SystemImageAdmin` use `RenderedConfigAdminMixin` (`common/rendered_config.py`) to add a read-only **Rendered Config** tab to the change page: every section is its own card — empty ones included, so every system shows the same panels — ordered with the "How this is merged" merge-rules card **first** (#423), then the inherits-from chain, Boot options, Configuration Parameters, per-list cards (scripts/Ansible with the layer(s) each value came from), skipped-`config_params` warnings, and the merged JSON (`systems/templates/admin/rendered_config.html`, `systems/test_rendered_config_tab.py`). After a system save, `warn_duplicate_ip_assignments()` only **warns** when a NIC's IP is already used by another system — the DB doesn't enforce unique IPs and duplicates like a VIP are intentional (#373, `systems/test_duplicate_ip_warning.py`). The System Images list shows each image's OS Distribution (#171), and its help text explains that renaming an image creates a copy rather than renaming in place (#424). `SystemGroupAdmin` sets `raw_id_fields = ['systems']` (#467): Django's default multi-select posted one form field per member system, which went over Django's 1000-POST-field limit for large groups (#464, worked around then by raising `DATA_UPLOAD_MAX_NUMBER_FIELDS` to 10000 — see [Configuration](../architecture/overview.md#configuration)); the raw-id widget posts the member ids as a single comma-separated field instead. Saving very large groups still requires MariaDB — SQLite allows only 999 variables per query (`systems/tests.py` `LargeSystemGroupAdminTests`, skipped on SQLite).

## Provisioning and PXE Boot

`System.provision` (default `True`) decides whether the node's next PXE boot installs/netboots it or lets it boot locally. It replaces the old "clear `bootable` on all NICs" trick, and is the handoff between mPCC, the iPXE template, and the RAM-image installer:

- The unauthenticated `/ipxe/` endpoint only serves a netboot config when the requesting NIC is `bootable` **and** `system.provision` is set; otherwise the template lets the node boot from disk. A N.A.D.S. boot always netboots regardless (`systems/views_noauth.py`, `systems/templates/ipxe`). The boot options (`install_kernel_cmdline`, `initial_mods`, `tmpfs_root_size`) come from the merged config — `System.config`, or the `__nads__` image's own merge for a N.A.D.S. boot — not just the distro's, so group/image/system values reach the node; the merged cmdline is still rendered as a Django template so it can use `{{ nic... }}` variables (`systems/test_ipxe_inherited_config.py`).
- `NetworkInterface.save()` enforces **at most one bootable NIC per system**: saving one as bootable clears it on the others, and the admin NIC inline rejects two (`systems/test_provision.py`).
- `System.enable_provisioning()` is the gate used by PXE Boot. It sets `provision` and returns `False` — changing nothing — when `System.provisioning_problem()` finds a blocker. `SystemPowerAPIView` turns that into HTTP **409** with the reason and does **not** reset the node, for `pxe`/`pxeefi` whether addressed by id, `?hostname=`, or BMC filter; the admin actions show the same message as an error.
- The PXE boot device itself is set by `systems/bootdev.py` `set_pxe_bootdev()` — raw `ipmitool chassis bootdev pxe` (`-E` keeps the password out of the process list) with a 30s timeout. When ipmitool fails, times out, or can't run, it returns a per-BMC 502/504/500 result and the caller leaves the node alone instead of resetting a node that would not netboot anyway, reporting the reason (#311, `systems/test_pxe_bootdev.py`).
- `System.boot_disk_problem()` mirrors the installer's own rule (`buildDisks()` in `static/mprov_stateful.py`): a stateful system needs at least one `DiskLayout`, and across all its layouts **exactly one** with a bootable partition (a data-disk layout without one is fine). Saves stay allowed — layouts and partitions are often attached after the system — so `systems/admin.py` `warn_boot_disk_problems()` and the `WarnBootDisksMixin` in `disklayouts/admin.py` only warn by name after saving a system or layout (issue #361).
- `POST /systems/?self` with `{"netboot": false}` clears the requesting system's `provision` flag (this is what `static/mprov_stateful.py` does once it has installed, so the node boots from disk); `{"netboot": true}` sets it and makes the requesting NIC the bootable one. `{"booted": true}` (posted by the post-boot script) stamps `System.last_booted` (migration 0073, read-only in API/admin) and logs to the `mprov.provisioning` logger for a time-to-provision metric (#433); `{"serial": ...}` records a serial change (see SystemSerialHistory). Written with queryset `update()` so boot reports never fire save signals or queue jobs (`systems/test_self_booted.py`). Any other key → 403, non-boolean → 400, both before anything changes; replies are JSON objects. For cert-authenticated agents the allowed `?self` keys are exactly what `pki/rules.py` lists ([PKI & Agent Auth](pki-and-agent-auth.md)).

The stateful install itself runs from the initramfs: `systems/templates/ipxe` injects `static/mprov_boot_init.sh` (modprobes each merged `initial_mods` entry first, recording loaded modules in `/tmp/init_mods`, then loads PCI-detected NIC/storage drivers and fetches the RAM image — retrying a failed download — and matches kernel options exactly rather than by prefix, issue #372, #285/#286, `systems/test_boot_init_cmdline.py`), then `static/mprov_stateful.py` + `mprov_stateful.sh` partition, rsync, install the bootloader, clear `provision`, and unmount everything under the install root before the sysrq reboot so GRUB sees a clean XFS log (issues #347, #352, #360). Node boot scripts no longer rely on the image's `/usr/bin/python3`: they prefer the job server's bundled interpreter at `/usr/libexec/mprov/bin/python3` (`image_python()` in `static/mprov_boot_init.sh` handles initramfs symlink checks; `mprov_stateful.sh` falls back for old 0.6.x images), so they keep working on images without python (issue #476, `systems/test_boot_init_python.py`). The installer now runs the image's udev (`systemd-udevd` with rules mirrored to `/run/udev/rules.d`) while installing, and `_waitForPartition()` settles udev before formatting, so layouts can name disks with `/dev/disk/by-id/` links (issue #410, `systems/test_stateful_udev.py`); partition devices are built the kernel's way — realpath'd disk basename plus the number, with a `p` when the name ends in a digit (`nvme0n1p1`, `mmcblk0p1`) — and `_checkDisks()` refuses to touch anything when a layout's disk doesn't exist (issue #391). Swap entries no longer create a `/newroot/none` mount (issue #275), kernel arguments without `=` survive into the installed GRUB command line (issue #276, `systems/test_stateful_grub_cmdline.py`), and the install does not finish until the `netboot: false` call to mPCC actually succeeds — failures are retried, so a dropped request can't leave the node netbooting forever (issues #323/#278, `systems/test_stateful_netboot.py`). Partition flags set the GPT type by contents — ESP only on the EFI partition (looked up by name; the images' pyparted has no `PARTITION_ESP`), RAID and swap flags where they apply; an earlier `setFlag(18)` on every partition made all of them ESP-typed (issue #279, `systems/test_stateful_partitions.py`). `_makeFS()`/`buildRAIDs()` format and assemble the device each layout partition actually received rather than assuming layout number = device suffix (issue #379, `systems/test_stateful_partition_devices.py`), and the fill partition's format/fstab decision checks the fill partition itself rather than the loop's last partition — a fill `/` followed by a RAID member was otherwise never formatted (issue #273). The diskless (stateless) path labels the tmpfs root for SELinux before switching to it: the initramfs loads the image's policy (`load_policy -i`), runs `setfiles` on `/`, and relabels `/run` and `/dev`, skipped when the image disables SELinux or the kernel boots `selinux=0` (issue #348); it also takes the provisioning NIC down before `switch_root` so the installed image's networking starts clean (issue #367, `static/mprov_boot_init.sh`).

**API** (`systems/views.py`): `SystemAPIView` (own `get()` with `SystemDetailSerializer`), `SystemRegAPIView` at `/systems/register/` (unauthenticated NADS registration, derives IPv6 link-local from MAC; each registration logs to the `mprov.nads` logger — "found on sw1 port 1/1 ... ready to be assigned" for a new MAC, "seen again" for a known MAC at a new location, or "registered to <system>" on a match — so operators notice new nodes; unauthenticated field values are control-char-escaped before logging to prevent log-line forgery, #170, `systems/test_register_log.py`), `SystemPowerAPIView` at `power/<action>/`, and the unauthenticated iPXE endpoint `views_noauth.py:IPXEAPIView` (see quickstart backlog for a full no-auth audit).

**Security-sensitive behaviors** (both have regression tests):
- `?hostname=` on `/power/<action>/` matches `hostname` **exactly**, not as a substring. It previously used `hostname__contains`, so one hostname powered on every system whose name contained that string (issue #332); `systems/test_power_by_hostname.py` pins the exact-match behavior.
- The unauthenticated `/ipxe/` and `/images/` endpoints identify the client by socket peer address (`REMOTE_ADDR`), not by the client-supplied `X-Forwarded-For` header. `X-Forwarded-For` is honored only when the connection provably arrives from a proxy listed in the `TRUSTED_PROXIES` setting (comma-separated exact IPs or CIDRs); the chain is then walked right to left and the first untrusted address is used. Before this fix, any client able to reach the HTTP port could forge the header and fetch any managed system's iPXE config, kernel, or initramfs (issue #319). See `systems/views_noauth.py`, `systems/test_noauth_xff.py`, and `TRUSTED_PROXIES` in [Configuration](../architecture/overview.md#configuration).
- The unauthenticated `/images/` redirect (and the repo redirect in `osmanagement/views_noauth.py`) picks a random responsive job server, then routes the client to that server's registered address on the client's own network when one exists — the per-network [JobServerAddress](jobs-and-scripts.md) list from its heartbeat (mprov_jobserver#114) — falling back to the server's primary address; IPv6 addresses are bracketed in the redirect URL (#309, `systems/test_images_jobservers.py`).

## BMC Credential Changes (`bmcrotate/`)

The `bmcrotate` app (#486) turns "Set BMC credentials" from store-only into a real push. `BMCCredentialsForm` gains a `mode` choice — `store` (the old behavior above), `change` (set them on the BMCs, then store what the BMCs accepted), or `check` — and non-store modes require a registered jobserver whose registration listed the `bmc-rotate` job module (else the form refuses, naming `MPROV_MODS`). `bmcrotate/logic.py` `start()` creates one `BMCRotation` ("BMC Credential Change": current/new user+password, JSON `candidates`, status `pending`/`running`/`succeeded`/`partial`/`failed`/`unreachable`/`unconfirmed`, outcome `method`/`tls_verified`/`stored`/`error`, `requested_by`, FK to its `Job`) plus one [job](jobs-and-scripts.md) per BMC. The jobserver claims it, then `GET /bmcrotations/<pk>/secret/` (flips pending→running) hands it the credentials and `POST /bmcrotations/<pk>/result/` reports back — both allowed only for the jobserver whose own certificate claimed the job (`pki/rules.py` rule; ownership re-checked in `bmcrotate/views.py`), and `jobqueue/views.py` refuses the claim with 409 unless that jobserver has a fresh `JobServerAddress` on the BMC's network.

`logic.apply_result()` stores **only a pair the jobserver just verified on the BMC**; secrets are cleared (`clear_secrets()`) once finished. A refusal before the BMC was touched (bad current credentials / unreachable, nothing verified) is a plain failure with no candidates; anything that may have changed the BMC lands `unconfirmed` and keeps up to three candidate pairs for the admin's "Find which credentials work" action. The History entry on `SystemBMC` names only the fields that actually changed ("BMC User", "BMC Password" — values never logged), and a `post_save` receiver on `Job` catches `bmc-rotate` jobs that end without reporting. Key sources: `bmcrotate/{models,logic,views,signals,admin}.py`, `systems/bmc_credentials.py`, `systems/templates/admin/bmc_credentials_form.html`.

## Networks (`networks/`)

Key models (`networks/models.py`): `NetworkType`; `Network` (slug, VLAN, subnet/CIDR, gateway/nameservers, `isdhcp`/`managedns`/`isbootable`, DHCP range); `Switch` and `SwitchPort` (the OneToOne target NICs attach to). Signals queue pxe/dns/dhcp update jobs on save and delete-jobs on delete, same pattern as systems.

**Subnet-change confirmation flow** (`networks/admin.py`, `networks/api_views.py`, `networks/utils.py`): editing a Network's subnet/netmask in the admin does not save immediately. The edit is stashed in the session and the operator is redirected to `networks/<pk>/update-with-confirmation/`, which previews every affected NIC/BMC IP rebased into the new network (`calculate_new_ip(s)` preserves host bits and nulls collisions/network/broadcast addresses) before applying; `preview-subnet-changes` exposes the same preview as JSON. This exists because one bad subnet edit would silently invalidate an entire rack's addressing.

**Network Summary tab** (`networks/admin.py`, `networks/templates/admin/networks/network_change_form.html`): the network change page has a read-only fieldset listing every NIC and BMC on the network — hostname (linking to the system change page with its NIC tab open, or the BMC tab for BMC rows), NIC name with a "BMC" badge, MAC, IP, switch/port, and bootable flag — sortable by hostname (default) or numerically by IP via header links that keep the tab open through the URL hash (issues #365/#366, `networks/test_network_summary.py`).

**API**: `NetworkAPIView`, `NetworkTypeAPIView`, `SwitchAPIView` (custom `?network=` slug filter), `SwitchPortAPIView`.

## Change guidance

- Anything that changes NIC/BMC/system fields: check the `common.render_config()` inheritance semantics (layers, `=`-prefix, YAML key merge) and the signal job payloads before editing; the jobserver's script runner must merge the same way.
- Admin form changes on the NIC inline: keep `systems/test_nic_inline.py` green (widget attributes are asserted exactly).
- Detail-serializer or security changes around BMC passwords: `systems/test_detail_serializer.py` asserts the flat list never exposes the BMC password.
- Key sources: `systems/{models,admin,views,views_noauth,serializers}.py`, `networks/{models,admin,api_views,utils}.py`.
