# Systems & Networking

These two apps hold the physical inventory: machines ([systems/](../../systems/)) and the L2/L3 topology they plug into ([networks/](../../networks/)). Their save/delete signals are the primary producers of jobs into the [Job Queue](jobs-and-scripts.md), which jobservers execute as pxe/dns/dhcp/image updates. All endpoints inherit [MProvView](../architecture/api-foundation.md) conventions, including `?detail` nested reads.

## Systems (`systems/`)

Key models (`systems/models.py`):

- **System** — a provisioned machine: `hostname`, `stateful` flag, `provision` flag (see [Provisioning and PXE Boot](#provisioning-and-pxe-boot)), FK to `SystemImage`, M2M to `DiskLayout` (see [OS & Disk Management](os-and-disk-management.md)), M2Ms to scripts/Ansible content, and a read-only `config` dict (cached property) merged by `common.render_config()`/`flat_config()` in `common/__init__.py` — the single implementation of config inheritance (the old `System.flatten_config()` is gone). Layers apply **OS Distro → System Groups (by name) → System Image → System**; a system's groups are its own plus its image's, each applied once. `install_kernel_cmdline` and `initial_mods` append down the stack (a leading `=` replaces everything above); `tmpfs_root_size`/`prov_interface` overwrite (0/empty inherits); `config_params` YAML merges by top-level key (invalid YAML or a non-mapping is skipped and reported); scripts and Ansible playbooks/roles/collections are the union of every layer's slugs (`systems/test_render_config.py`). The jobserver's script runner merges the same way — keep the two in step.
- **NetworkInterface** — belongs to a System, attaches one-to-one to a `SwitchPort`, carries `ipaddress`/MAC/bootable flags; IPv6 link-local/guarded-global addresses are computed alongside. Its `hostname` is a copy of the System's, kept in step by `NetworkInterface.save()`, by `System.save()` (which updates the NIC copies in the same transaction on rename, so DHCP/DNS and register_IPv6_ll.py never see a stale name), and by read-only `hostname` in both NIC serializers (#382, `systems/test_nic_hostname.py`).
- **SystemBMC** — "Power Management" credentials per system (inline max 1; password field uses `PasswordInput` and is never exposed on flat API lists). On the API the password is served only when the request is scoped to one system — `GET /systembmcs/<pk>/` or `GET /systembmcs/?system=ID` (the query mprov_scripts' setupBMC.py makes); an unscoped `?detail` returns the same nesting via `SystemBMCDetailNoPasswordSerializer` with the password left out, so one unscoped GET cannot dump every BMC password (issue #316, `systems/views.py`, `systems/test_detail_serializer.py`).
- **SystemImage** — the PXE-bootable image definition (slug PK, `version`, `needs_rebuild`, `customIPXE`). It is a config-inheritance layer in its own right (distro → image's groups → image) and has the same cached `config` property as System; the `/systemimages/` serializers serve it read-only in list and detail so the jobserver's script runner can read the merge instead of redoing it (`systems/models.py`, `systems/test_render_config.py`).
- Plus `SystemGroup`, `SystemModel`, `SystemLocation`, and `NADSSystem` (switch-based auto-discovery: an NADS post_save copies the discovered MAC onto the system's bootable NIC).

**Signals are the behavior**: saving a System/NIC/BMC queues `pxe-update`, `dns-update`, `dhcp-update` jobs; saving a `SystemImage` bumps its version, clears assigned jobservers, and queues `image-update`; deleting an image queues per-server `image-delete`. These write into the [job queue](jobs-and-scripts.md) — mPCC never touches TFTP/DNS directly.

**Admin** (`systems/admin.py`): `SystemAdmin` embeds a `NetworkInterfaceInline` (custom `NetForm` widgets; a formset restricts `switch_port` choices to unassigned ports — the IP Address widget deliberately has no narrowing style, enforced by `systems/test_nic_inline.py`) and a `BMCInline`. IPMI power actions (`sys_on/off/cycle/pxe/pxe_efi`) use `pyipmi` plus raw `ipmitool` with the `IPMI_PASSWORD` env var. A `bulk_update` admin action (template `systems/templates/admin/system_bulk_change_form.html`) can set `provision`, and a `_copy_to_new` button clones systems. Both `SystemAdmin` and `SystemImageAdmin` use `RenderedConfigAdminMixin` (`common/rendered_config.py`) to add a read-only **Rendered Config** tab to the change page: the inheritance layers in order (each linking to its page), the boot options/params/scripts/Ansible lists with the layer(s) each value came from, skipped-`config_params` warnings, the merge rules, and the merged JSON (`systems/templates/admin/rendered_config.html`, `systems/test_rendered_config_tab.py`).

## Provisioning and PXE Boot

`System.provision` (default `True`) decides whether the node's next PXE boot installs/netboots it or lets it boot locally. It replaces the old "clear `bootable` on all NICs" trick, and is the handoff between mPCC, the iPXE template, and the RAM-image installer:

- The unauthenticated `/ipxe/` endpoint only serves a netboot config when the requesting NIC is `bootable` **and** `system.provision` is set; otherwise the template lets the node boot from disk. A N.A.D.S. boot always netboots regardless (`systems/views_noauth.py`, `systems/templates/ipxe`). The boot options (`install_kernel_cmdline`, `initial_mods`, `tmpfs_root_size`) come from the merged config — `System.config`, or the `__nads__` image's own merge for a N.A.D.S. boot — not just the distro's, so group/image/system values reach the node; the merged cmdline is still rendered as a Django template so it can use `{{ nic... }}` variables (`systems/test_ipxe_inherited_config.py`).
- `NetworkInterface.save()` enforces **at most one bootable NIC per system**: saving one as bootable clears it on the others, and the admin NIC inline rejects two (`systems/test_provision.py`).
- `System.enable_provisioning()` is the gate used by PXE Boot. It sets `provision` and returns `False` — changing nothing — when `System.provisioning_problem()` finds a blocker. `SystemPowerAPIView` turns that into HTTP **409** with the reason and does **not** reset the node, for `pxe`/`pxeefi` whether addressed by id, `?hostname=`, or BMC filter; the admin actions show the same message as an error.
- `System.boot_disk_problem()` mirrors the installer's own rule (`buildDisks()` in `static/mprov_stateful.py`): a stateful system needs at least one `DiskLayout`, and across all its layouts **exactly one** with a bootable partition (a data-disk layout without one is fine). Saves stay allowed — layouts and partitions are often attached after the system — so `systems/admin.py` `warn_boot_disk_problems()` and the `WarnBootDisksMixin` in `disklayouts/admin.py` only warn by name after saving a system or layout (issue #361).
- `POST /systems/?self` with `{"netboot": false}` clears the requesting system's `provision` flag (this is what `static/mprov_stateful.py` does once it has installed, so the node boots from disk); `{"netboot": true}` sets it and makes the requesting NIC the bootable one. Any other key → 403, non-boolean → 400, both before anything changes; replies are JSON objects.

The stateful install itself runs from the initramfs: `systems/templates/ipxe` injects `static/mprov_boot_init.sh` (modprobes each merged `initial_mods` entry first, recording loaded modules in `/tmp/init_mods`, then loads PCI-detected NIC/storage drivers and fetches the RAM image — issue #372), then `static/mprov_stateful.py` + `mprov_stateful.sh` partition, rsync, install the bootloader, clear `provision`, and unmount everything under the install root before the sysrq reboot so GRUB sees a clean XFS log (issues #347, #352, #360). Partition flags set the GPT type by contents — ESP only on the EFI partition (looked up by name; the images' pyparted has no `PARTITION_ESP`), RAID and swap flags where they apply; an earlier `setFlag(18)` on every partition made all of them ESP-typed (issue #279, `systems/test_stateful_partitions.py`). `_makeFS()`/`buildRAIDs()` format and assemble the device each layout partition actually received rather than assuming layout number = device suffix (issue #379, `systems/test_stateful_partition_devices.py`), and the fill partition's format/fstab decision checks the fill partition itself rather than the loop's last partition — a fill `/` followed by a RAID member was otherwise never formatted (issue #273). The diskless (stateless) path labels the tmpfs root for SELinux before switching to it: the initramfs loads the image's policy (`load_policy -i`), runs `setfiles` on `/`, and relabels `/run` and `/dev`, skipped when the image disables SELinux or the kernel boots `selinux=0` (issue #348).

**API** (`systems/views.py`): `SystemAPIView` (own `get()` with `SystemDetailSerializer`), `SystemRegAPIView` at `/systems/register/` (unauthenticated NADS registration, derives IPv6 link-local from MAC), `SystemPowerAPIView` at `power/<action>/`, and the unauthenticated iPXE endpoint `views_noauth.py:IPXEAPIView` (see quickstart backlog for a full no-auth audit).

**Security-sensitive behaviors** (both have regression tests):
- `?hostname=` on `/power/<action>/` matches `hostname` **exactly**, not as a substring. It previously used `hostname__contains`, so one hostname powered on every system whose name contained that string (issue #332); `systems/test_power_by_hostname.py` pins the exact-match behavior.
- The unauthenticated `/ipxe/` and `/images/` endpoints identify the client by socket peer address (`REMOTE_ADDR`), not by the client-supplied `X-Forwarded-For` header. `X-Forwarded-For` is honored only when the connection provably arrives from a proxy listed in the `TRUSTED_PROXIES` setting (comma-separated exact IPs or CIDRs); the chain is then walked right to left and the first untrusted address is used. Before this fix, any client able to reach the HTTP port could forge the header and fetch any managed system's iPXE config, kernel, or initramfs (issue #319). See `systems/views_noauth.py`, `systems/test_noauth_xff.py`, and `TRUSTED_PROXIES` in [Configuration](../architecture/overview.md#configuration).

## Networks (`networks/`)

Key models (`networks/models.py`): `NetworkType`; `Network` (slug, VLAN, subnet/CIDR, gateway/nameservers, `isdhcp`/`managedns`/`isbootable`, DHCP range); `Switch` and `SwitchPort` (the OneToOne target NICs attach to). Signals queue pxe/dns/dhcp update jobs on save and delete-jobs on delete, same pattern as systems.

**Subnet-change confirmation flow** (`networks/admin.py`, `networks/api_views.py`, `networks/utils.py`): editing a Network's subnet/netmask in the admin does not save immediately. The edit is stashed in the session and the operator is redirected to `networks/<pk>/update-with-confirmation/`, which previews every affected NIC/BMC IP rebased into the new network (`calculate_new_ip(s)` preserves host bits and nulls collisions/network/broadcast addresses) before applying; `preview-subnet-changes` exposes the same preview as JSON. This exists because one bad subnet edit would silently invalidate an entire rack's addressing.

**Network Summary tab** (`networks/admin.py`, `networks/templates/admin/networks/network_change_form.html`): the network change page has a read-only fieldset listing every NIC and BMC on the network — hostname (linking to the system change page with its NIC tab open, or the BMC tab for BMC rows), NIC name with a "BMC" badge, MAC, IP, switch/port, and bootable flag — sortable by hostname (default) or numerically by IP via header links that keep the tab open through the URL hash (issues #365/#366, `networks/test_network_summary.py`).

**API**: `NetworkAPIView`, `NetworkTypeAPIView`, `SwitchAPIView` (custom `?network=` slug filter), `SwitchPortAPIView`.

## Change guidance

- Anything that changes NIC/BMC/system fields: check the `common.render_config()` inheritance semantics (layers, `=`-prefix, YAML key merge) and the signal job payloads before editing; the jobserver's script runner must merge the same way.
- Admin form changes on the NIC inline: keep `systems/test_nic_inline.py` green (widget attributes are asserted exactly).
- Detail-serializer or security changes around BMC passwords: `systems/test_detail_serializer.py` asserts the flat list never exposes the BMC password.
- Key sources: `systems/{models,admin,views,views_noauth,serializers}.py`, `networks/{models,admin,api_views,utils}.py`.
